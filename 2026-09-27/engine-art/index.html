#06 · unreal

UE Control Rig + Python：用 Python 建／改 Rig，讓 RigVM 專注執行

這套做法把 Python 定位成 Control Rig 的 authoring／automation 層：可建立或載入 ControlRigBlueprint、改 hierarchy、graph nodes、metadata 與 setup；真正的 rig graph 仍由 RigVM 執行，Python Log 則可反查編輯器操作對應的指令。

Unreal ★★★★☆
完整分析

技術／流程變更

來源把責任切成 Python authoring、RigVM execution：Python 適合批次建立 hierarchy、controls、nodes 與 metadata，不是拿來取代每幀執行的 Control Rig graph。這能避免把 editor automation 與 runtime rig logic 混在一起。

Production 影響

對大量角色或重複 rig setup，Python 可以把命名、骨架結構、常用 function／library 與 metadata 變成一致的建立流程；Python Log／Copy Python Script 也能把手動操作轉成可重複工具，降低每個角色重新點一次的成本。

導入測試與限制

自動化前仍要先固定 Skeletal Mesh、hierarchy 與 engine-side rig 規格。應用同一腳本測不同角色、Control Rig 編譯、Sequencer／Animation Blueprint 與版本升級後的 API 相容性，避免工具腳本比 rig 本身更難維護。

#07 · unreal

InstantRDV for UE5.8：從 DepthBuffer 即時建立 GPU Voxel Scene，不依賴 Hardware RT

InstantRDV 直接從 Main View 的 DepthBuffer 在 GPU 建立 Voxel Scene，不需要額外 Geometry Pass 或 CPU voxelization；資料以 BBV（Bitmask Brick Voxel）管理，可隨相機更新並由 Compute Shader 做 voxel ray tracing，UE5.8 範例以 MIT 授權公開。

Unreal ★★★★☆
完整分析

技術／流程變更

它利用 rasterization 已有的深度資訊重建 voxel scene，再以 brick 單位保存 radiance；因此核心方向是重用現有畫面資料，而不是再跑一套完整幾何收集或依賴 Hardware Ray Tracing Scene。

Production 影響

對需要非 Lumen GI、可攜 voxel lighting 或研究自訂 GI 的 UE 專案，這是一個可直接拆 code／sample 的技術原型；特別適合評估純 GPU voxel 更新與 compute ray tracing 能否接進自家 rendering path。

導入測試與限制

目前屬開源 demo／plugin，而不是成熟替代 Lumen 的通用方案。要實測鏡頭高速移動、薄片幾何、遮擋變化、dynamic object、不同解析度與 GPU memory／compute cost，再判斷可用場景。

BRIEF｜來源已驗證；證據深度較有限，完整分析會明確區分已知資訊與待驗證事項。

#08 · unity

POLYPAINT：直接在 Unity Scene View 畫 Vertex Color 與 Vertex Normal

POLYPAINT 讓美術直接在 Unity Editor 編輯 Vertex Color 與 Vertex Normal，支援 RGBA channel、vertex／edge／face target、Marquee／Lasso mask、多 mesh 編輯、Normal Smooth／Hard，以及 reimport 後保留資料與 Snapshot 轉移。

Unity ★★★★☆
完整分析

技術／流程變更

原本需要回 Blender／Maya 修改的 vertex color 或 normal，可直接在 Unity Scene View 完成；工具也提供 channel 限定、selection mask、split／merge shared vertex 與 quick action，讓資料修改更接近引擎端結果。

Production 影響

對以 Vertex Color 做材質混合、shader mask、NPR 假光或低模風格法線控制的流程很直接：美術可在最終 shader／lighting 環境內調整，不必反覆 FBX 往返，Snapshot 也有利於版本比較與跨場景搬移。

導入測試與限制

導入前要確認 prefab／mesh reimport、LOD、mesh compression、shared vertex split 及版本控制後資料是否穩定保存；若專案會重新產生 mesh，也要驗證 Snapshot 或 painted data 的重套流程。

BRIEF｜來源已驗證；證據深度較有限，完整分析會明確區分已知資訊與待驗證事項。

#14 · unity

Unity URP Terrain Lit Shader Graph：官方 Terrain 節點可直接讀 Layer 貼圖與 Mask

Unity 的 Terrain Lit Shader Graph 現在提供專用 Terrain nodes；其中 Terrain Texture 依 layer index 取得 Diffuse、Normal、Mask、Layer Masks 或 Holes，並輸出對應的 PBR 資訊，讓自訂 Terrain shader 不必再靠過去的繞路做法。

Unity ★★★☆☆
完整分析

技術／流程變更

建立路徑直接出現在 Create → Shader Graph → URP → Terrain Lit Shader Graph。Terrain Texture node 以 layer index 讀 Terrain layer 資料，除了 texture 本身，也能回報該類貼圖是否存在與其他 PBR outputs。

Production 影響

對 stylized terrain 或需要自訂坡度、濕潤、積雪、NPR 分段的 Unity 場景，官方 Terrain Graph 讓美術可以在保留 Terrain authoring 的前提下擴充 shader，而不是改成一般 mesh 才能做自訂材質。

導入測試與限制

教學針對目前 URP／Shader Graph 的官方支援；導入時要用實際 Terrain Layers 測四層以上混合、Normal／Mask、Holes、GPU instancing、Terrain Detail 與目標平台效能，確認自訂 graph 沒破壞原生 Terrain 行為。

BRIEF｜來源已驗證；證據深度較有限，完整分析會明確區分已知資訊與待驗證事項。

#15 · rendering

OpenUSD 26.03：3D Gaussian Splat 有正式 Prim Schema 與 Reference Renderer

OpenUSD 26.03 新增 3D Gaussian Splatting 支援，以新的 USD prim schema 表示 3DGS 資料，並提供 reference Gaussian Splat renderer；這讓 splat 資料開始能走 USD 的場景描述與交換框架，而不只依賴各工具自己的格式。

渲染 ★★★☆☆
完整分析

技術／流程變更

3DGS 被提升成可描述的 USD prim type，並有 hdParticleField reference renderer 作為實作基準。這代表 DCC、renderer 與 pipeline tool 可以針對同一 schema 交換 splat，而不必每套工具各自定義資料結構。

Production 影響

對 VFX、virtual production、animation 與 visualization，真正價值是 pipeline interoperability：掃描或生成的 splat 若能進 USD stage，就有機會和既有 camera、lighting、asset hierarchy 與 publishing 工具共存。

導入測試與限制

標準有 schema 不代表所有 DCC／renderer 已完整支援。導入時要逐一驗證 import／export、attribute 保留、transform、large-scene performance 與 renderer parity，並確認目前使用的 USD 版本是否包含 26.03 定義。

BRIEF｜來源已驗證；證據深度較有限，完整分析會明確區分已知資訊與待驗證事項。

#22 · unreal

Pose Overlay 1.0.2 for UE5.8：可重用 Pose State、逐骨疊加、Aim Offset 與 IK Mapping

Pose Overlay 在 UE5.8 以 Control Rig-based editor 建立可重用 pose states，不需複製原 animation clip；可為 gameplay context 做局部 override，逐骨控制 Overlay Weight／Source Motion／Space Blend，並支援 Aim Offset、IK mapping 與 runtime stacking。

Unreal ★★★☆☆
完整分析

技術／流程變更

核心是把姿勢修正做成獨立、可重用的 state，再疊到來源 animation 上；每根 bone 可決定要覆蓋、跟隨原 motion 或穩定 rotation，Aim profile 與 IK target 也能放在同一套 hierarchy。

Production 影響

對共用 locomotion 但不同武器、體型或 gameplay context 的角色，overlay 能減少複製大量近似 animation clip。局部修正留在 state／context 層，也比較容易追蹤『基礎動畫』與『角色特例』的責任。

導入測試與限制

1.0.2 目前標示支援 UE5.8；要測 Control Rig／Animation Blueprint 接法、兩手持武器 IK、network runtime stacking、bake 回 clip 與大量 state 的管理成本，再決定是否取代既有 additive／layered blend 流程。

BRIEF｜來源已驗證；證據深度較有限，完整分析會明確區分已知資訊與待驗證事項。
