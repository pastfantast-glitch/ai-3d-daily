#01 · blender

Blender 5.3 Alpha 原生支援 Gaussian Splat 匯入與渲染，但 export 與色彩仍有限制

Blender 5.3 開發版加入 PLY／SPZ Gaussian Splat 匯入與各 render engine 渲染，讓掃描／照片重建資料不必先靠第三方 add-on；目前仍沒有 splat export，且效能、線性色彩與 Apply Transform 有已知限制。

Blender ★★★★★
完整分析

DCC 支援變更

Gaussian Splat 開始成為 Blender 原生可匯入、可渲染的資料類型，支援 PLY 與 SPZ，並可在 Blender 各 render engine 中使用；這讓 capture／3DGS 資料能更直接進入一般 DCC 場景與鏡頭流程。

Production 價值

若團隊用照片或影片重建環境，原生支援可減少外掛版本綁定，並讓 mesh、camera、lighting 與 splat 同場整合；對背景、previs、場景 reference 和 hybrid rendering 都有直接工作流價值。

導入限制

目前仍是 5.3 Alpha，官方資訊指出 export 尚未支援，Cycles／EEVEE 線性色彩顯示也不完全正確，Apply Transform 還有 scale／rotation／spherical harmonics 問題；現階段應定位為測試而非正式資產交付。

#13 · substance

Substance Designer SDF 小熊軟糖：用 Shape Splatter v2＋色彩分層假出半透明

QiYu Dai 在 Designer 以 SDF 建立小熊形狀、Shape Splatter v2 生成材料，再用 base/AO/specular 等色彩層模擬平面材質上的 jelly 半透明，示範不依賴完整幾何也能做 stylized translucent look。

Substance ★★★★☆
完整分析

SDF 材質技術流程

Designer 先用 SDF 建立可程序控制的小熊形狀，再交給 Shape Splatter v2 分布；這種技術流程把形狀生成與材質控制分離，適合大量變體與可重用 graph。

Production 價值

用 AO、edge specular、roughness 與色彩分層在平面材質上近似 jelly 半透明，可避免為每個圖案建立完整幾何，對 stylized material library 與快速換色換形狀有直接製作價值。

導入測試與限制

這種方法主要是假半透明，不等同真實體積傳輸；進遊戲前要在不同燈光、背景、mip 距離與 tone mapping 下實測，確認材質不會失去厚度感，必要時再補 shader 端近似。

#14 · blender

Blender 5.3 Layered Compositing 主 PR 已合併，Compositor Effects 進入正式整合階段

Blender Compositor 9/10 會議紀錄指出 Layered Compositing 的主要 PR 已合併並預計進 5.3，後續仍在調整 Scene Effect/UI，代表分層合成工作流已從研究走向可測試整合。

Blender ★★★☆☆
完整分析

Compositor 技術流程

Layered Compositing 主 PR 已合併到 Blender 5.3 開發線，技術方向是把 Scene Effect 與多層合成結果更完整地留在 Compositor 工作流中，減少外部後製工具往返。

Production 影響

對 NPR、動畫與 shot-based pipeline，分層合成若能直接在 Blender 內管理，可降低 EXR 中間檔、版本同步與 review 成本，並讓 lighting/compositing 調整更靠近原始 scene。

成熟度與測試

目前仍在 5.3 開發期，UI 與命名持續調整；導入前應用代表性 shot 驗證 node 行為、color management、render layer 輸出與 farm 相容，尚不適合鎖定正式 template。

#15 · blender

Blender Cycles 規劃 CUDA 12→13：Windows ARM64 與新 GPU 工具鏈進入測試

9/15 Render & Cycles 會議提到準備切換到 CUDA 13.4.x，並處理 Windows ARM64、Intel library 與 compiler/driver 相容問題；對 render farm 與自建 Blender 發行版屬於值得追蹤的工具鏈變動。

Blender ★★★☆☆
完整分析

Render 技術變更

Cycles 團隊正規劃 CUDA 12→13 的工具鏈切換，並同步處理 Windows ARM64、Intel libraries 與 compiler/driver 問題；這屬於渲染後端與 build baseline 的技術變更。

Production 影響

即使 scene 功能沒有改，CUDA major version 仍可能改變 render farm 的 driver baseline、自建 Blender 發行版與 GPU 節點維護成本；大型團隊需把工具鏈版本納入部署矩陣。

導入風險與驗證

正式切換前應保留既有 farm，等 daily/beta 後用代表性 Cycles 場景實測 kernel compile、OptiX/CUDA fallback、driver 相容性與 ARM64 節點；未驗證前不宜直接更新所有 render node。
