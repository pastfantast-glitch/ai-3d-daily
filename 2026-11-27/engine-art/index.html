Godot 4.8 beta 5 修正 MetalFX 升頻與 Trail3D 更新問題

Godot 4.8 beta 5 以回歸修正為主，處理 MetalFX 時域升頻的抖動偏移及 Trail3D 更新問題；官方仍將它定位為預發布版本，.NET 組建最低需求改為 .NET 10。

升頻與軌跡更新列入修正

變更表列出 MetalFX 時域升頻抖動偏移的單位與正負號修正，以及停用 process 時 Trail3D 的更新修正；這些是 beta 4 到 beta 5 的差異，並非整個 4.8 功能清單。

編輯器與 C# 專案也受影響

Find in Files 複製篩選器、繼續執行時顯示 Game dock 都有修正；C# 翻譯外掛改以標準方式註冊，避免覆蓋使用者外掛，與純渲染修正分屬不同工作環節。

預發布狀態與執行環境需區分

官方提醒此版仍是預發布軟體，已知問題清單也會繼續更新；.NET 組建需要 .NET 10 或更新版本，不能沿用先前最低 .NET 8 的假設，標準組建則提供 GDScript 和 GDExtension。

Sovereign Tower 製作案例：時間回溯存檔與 Godot 資產整合

Wild Wits Games 分享 Sovereign Tower 的製作經驗：時間回溯不能只還原普通存檔，團隊拆分敘事狀態；美術則透過 Godot 場景系統更新肖像，複雜 UI 交由技術成員處理。

回溯狀態要保留玩家已知資訊

每個遊玩循環需要上午與下午兩份存檔，且必須記住先前循環資訊；主角回溯後仍保留所知內容，因此團隊把需保存的資料細分，而非直接恢復一份完整舊狀態。

場景系統支援美術直接迭代

肖像等簡單資產由美術負責人放入儲存庫並在 Godot 更新，較複雜的 UI 由程式或技術美術整合；團隊表示場景系統讓美術可自行調整畫面，減少每次微調都經過程式人員。

分支規模與測試仍有成本

大量敘事變數和角色讓回溯存檔難以完整測試，上市後仍有問題要修；敘事設計也受字數與在地化預算約束，團隊刪減部分變體，不能將這套方法視為沒有測試和製作成本的方案。
