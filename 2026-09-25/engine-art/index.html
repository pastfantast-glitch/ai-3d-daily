#15 · tools

Mold：Unity / Godot 共用的即時 Vector Graphics Library

Mold 提供 2D／3D 幾何 primitive 與 shader-based vector quality，目標是在 Unity、Godot 中以即時圖形而非預製圖檔建立風格化畫面。

引擎工具 ★★★★☆
完整分析

技術／流程變更

Mold 把常用 2D／3D primitive 與向量感抗鋸齒放進 runtime library，並以 vertex shader 變形取得不同幾何，讓 Unity／Godot 可直接『畫形狀』而不是依賴大量預製 sprite 或 mesh。

Production 影響

對 UI、簡約風格、程序化圖形與大量 icon／primitive 的遊戲很有潛力，同一套視覺邏輯還可跨 Unity 與 Godot，降低素材重製與解析度變體管理。

導入測試與限制

目前仍在開發且不同引擎版本的 feature parity、batching、shader 相容性與行動裝置效能需要實測；若要 shipping 應先用代表性 UI／場景建立 profiler baseline。

Unity 6000.6.3f1：Graphics API 小改動與多項 Editor／渲染修正

Unity 6000.6.3f1 於 9/24 發布，新增 Graphics.disableDepthAndStencilBuffers 查詢 API，並包含 Android、2D、資產與多項穩定性修正及已知問題。

Unity ★★★☆☆
完整分析

技術／流程變更

這是 6000.6 系列維護版，Graphics 新增可讀取 Disable Depth and Stencil Buffers 設定的 API，同時更新 Android Gradle Plugin 並修正一批 Editor、2D 與匯入相關問題。

Production 影響

對 production 的直接價值是版本評估：若專案依賴 6000.6，可用 release notes 對照目前 shader、Texture2DArray、Play Mode 與 Android build 問題，判斷是否值得升版。

導入測試與限制

官方同時列出 Vulkan crash、async shader compilation deadlock、UnloadUnusedAssets 變慢等 known issues；正式升級前必須用專案 build、Graphics Jobs 與目標裝置做回歸。

#20 · unreal

Unreal Engine 5.8 PCG：從 Asset Utility 到 Biome / World Generation 的程序化框架

Epic 官方文件定義 UE5.8 PCG Framework，可在 Editor 與 Runtime 以 procedural graph 建立建築、biome、vegetation 與世界內容。

Unreal ★★★☆☆
完整分析

技術／流程變更

PCG Framework 以 point、density、attribute 與 graph node 組成程序內容流程，可從單一 asset utility 擴充到 building、biome 與整個 world generation，並提供 GPU processing 與 runtime generation 路徑。

Production 影響

對場景美術最直接的價值是把散佈、規則與變體從手工擺放轉成可重跑 graph，適合植被、模組建築與大世界；也更容易讓技術美術把規則封裝成 artist-facing 工具。

導入測試與限制

官方文件是能力參考，不等同任何專案都適合 Runtime PCG；需要用實際 density、World Partition、Nanite 資產量與 cook 時間測試 Editor 迭代及 runtime 成本。

Godot PS1-style Rendering：從原始硬體限制反推復古畫面規則

Calin P 以自製 PS1 emulator 的硬體理解拆解 PS1 視覺特徵，並提供在 Godot 重建該 rendering aesthetic 的方法與 add-on。

渲染 ★★★☆☆
完整分析

技術／流程變更

這個案例不是只套低解析 filter，而是從 PS1 hardware behavior 反推影像特徵，再把對應限制與 rendering 規則搬到 Godot，讓復古風格有可解釋的技術來源。

Production 影響

對 stylized rendering 的價值是提供一種『先理解限制、再設計 shader』的工作法，可避免只靠貼圖降解析度卻缺少 vertex／UV／sampling 等整體一致性。

導入測試與限制

目前來源未提供所有平台與 renderer 的完整測試矩陣；使用 add-on 前要確認 Godot 版本、Forward+/Mobile renderer、後處理順序與不同解析度下的 artifact 是否符合美術需求。
