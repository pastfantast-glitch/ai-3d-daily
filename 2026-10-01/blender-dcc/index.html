#02 · blender

Fyr Baker：把 Marmoset 式貼圖烘焙流程帶進 Blender

Fyr Baker 把 Marmoset Toolbag 類型的專用烘焙流程帶進 Blender：設定可保存在場景內，支援背景 GPU 烘焙、高低模投射、包覆網格、環境遮蔽、曲率與 ID 等貼圖，並可依 Substance Painter、Unreal、Unity 流程整理輸出。

Blender ★★★★☆
完整分析

技術／流程變更

它的核心不是單純增加一個 Bake 按鈕，而是把 Marmoset Toolbag 式的迭代方式搬進 Blender：設定留在場景、結果可預覽，cage 可直接調整，修改模型後只需重烘需要的 maps，不必來回切換獨立軟體。

Production 影響

對角色／道具 Texture 流程，可直接拿同一個 high-low asset 比較 Blender 原生、Fyr Baker 與既有 Marmoset／Substance 路徑，記錄 cage 調整、批次輸出、命名與引擎 preset 是否真的減少人工步驟。

導入測試與限制

目前 add-on 需求為 Blender 5.1 以上，GPU 加速效果也與平台／顯卡支援有關；正式導入仍要測 UDIM、複雜材質節點、批次資產與失敗重烘時的穩定性。

#03 · blender

Blender Grease Pencil Shape Keys：角色 Rig 實測與目前限制

Grease Pencil 的 Shape Keys 可用 Bézier 曲線保存並快速切換 2D 形狀狀態，Mumu Mundo 也把它接到角色 Rig 實測；目前仍有控制點難選、Edit Mode 只能看單一 Shape Key、Armature／Driver 互動與大幅變形填色失真的問題。

Blender ★★★★☆
完整分析

技術／流程變更

對 2D rigging 來說，Shape Keys 讓嘴型、表情或局部輪廓不必完全依賴骨架變形，而能保存多個明確 shape state；這會讓 Grease Pencil 更接近傳統 2D deformation 與 Blender rig 系統的混合流程。

Production 影響

若用在角色製作，可先建立幾組嘴型與大表情，測試 Shape Key、Armature、Driver 疊加後的可編輯性與 animator 操作負擔；這比只測單一靜態形狀更能看出它是否適合正式 Rig。

導入測試與限制

目前功能仍在開發中，控制點選取、Driver 後數值鎖定、Bézier 顯示與大變形 fill 都有已知限制；適合做技術預研與 Rig prototype，尚不宜直接視為成熟量產方案。

BRIEF｜來源已驗證；證據深度較有限，完整分析會明確區分已知資訊與待驗證事項。

#05 · substance

Substance Designer → ZBrush → Maya：複雜硬表面圖樣的模組化流程

Nate Stephens 示範先在 Substance Designer 以程序化方式建立複雜裝飾圖樣與 height template，再進 ZBrush 雕刻、retopo，最後到 Maya 補拓撲與 UV；重點是把可反覆修改的圖樣網路當成環境資產細節來源。

Substance ★★★☆☆
完整分析

技術／流程變更

這條流程把「圖樣設計」從一次性雕刻拆成可參數化來源：Designer 負責迭代形狀與高度資料，ZBrush 負責立體精修，Maya 處理最終拓撲與 UV，因此同一套 network 能延伸到多個同系列資產。

Production 影響

對場景／Hard Surface 團隊，可挑一組常重複出現的門飾、地磚或牆面 ornament，測試程序化 template 是否能維持 texel density、造型一致性並減少重複雕刻時間。

導入測試與限制

這是 2019 年的教學內容，工具版本已舊；適合吸收「程序化圖樣 → 雕刻 → retopo」的流程觀念，但節點、UI 與現行 Substance／ZBrush／Maya 功能需要用目前版本重新驗證。

#07 · blender

Blender Previous Versions：舊版下載、Source Archive 與相容性回溯

Blender 官方長期保留歷代版本與 source archive，讓舊 .blend 專案可回到當時版本重現；頁面也提醒部分舊版需要特定硬體與作業系統，因此它更像 legacy pipeline 的回溯資源，而不是新功能更新。

Blender ★★★☆☆
完整分析

技術／流程變更

對長期專案而言，保留舊版執行環境很重要：當 add-on、Python API、shader 或模擬結果因升版改變時，可先用原版本確認問題來自資產本身還是版本差異，再決定 migration 策略。

Production 影響

團隊可把關鍵專案的 Blender 版本、add-on 版本與 Python 環境寫進 manifest，必要時從官方 archive 重建；比只保存 .blend 檔更能提高數年後重開案或修舊資產的成功率。

導入測試與限制

這個頁面本身不是 2026 的技術更新，資訊價值在版本保存與相容性追蹤；正式 production 仍應優先使用受支援的 Stable／LTS 版本，舊版只在重現與遷移情境使用。

Cinema 4D 2026.4：官方 MCP 自然語言自動化介面

Cinema 4D 2026.4 新增官方 MCP Server，可把 Claude Desktop、ChatGPT Desktop 等外部 AI 接到 Cinema 4D，以自然語言執行程序化、反覆或重複任務；Server 預設關閉，可在本機運行，所有動作也會進 undo stack。

其他 DCC ★★★☆☆
完整分析

技術／流程變更

對 Motion／3D 團隊，MCP 最適合先處理可描述、可驗證、可撤銷的重複工作，例如批次調整物件、建立規則化場景操作或快速迭代參數，而不是把造型判斷與最終視覺決策交給模型。

實測時可把同一個批次任務分別用手動、Python／Script 與 MCP 完成，量測步驟、錯誤率、回退能力與維護成本，才能判斷自然語言介面是否真的比既有 automation 更有效率。

導入測試與限制

MCP Server 只在完整版 Cinema 4D 提供，不適用 Lite、Team Render 或 command-line render；若連雲端 AI，還要另外評估場景資料外送、權限與公司資產保密規範。

#13 · blender

Nashville 機場巨型螢幕：Blender 程序化與跨軟體製作流程

Gentilhomme 為 Nashville 機場兩面最高 11200×2160 的巨型 LED 螢幕製作超過 40 分鐘內容，其中 6 段全 CGI 使用 Blender；Geometry Nodes 負責大量程序化排列，也接收 Maya／Substance 的 OBJ＋4K UDIM 與 Houdini 模擬，最後以 Cycles multipass EXR 進 After Effects。

Blender ★★★☆☆
完整分析

技術／流程變更

案例顯示 Blender 在這裡不是孤立 DCC，而是 pipeline hub：外部模型、UDIM、Houdini simulation 都可進場景與 Geometry Nodes，再由 Cycles 統一輸出；團隊甚至自製 render script 管理檔名、frame mapping、Deadline 與 multipass。

Production 影響

對跨 DCC 場景團隊，最值得借鏡的是把「容易改的東西留到最便宜的階段」：例如燈光時序先分層輸出，再在 comp retime，而不是每次修改都重新做高解析 3D render。

導入測試與限制

超寬螢幕與長鏡頭讓這個專案的 render farm、採樣與細節需求遠高於一般遊戲畫面；方法可借鏡，但 20 台 render node、超高解析 EXR 與離線 Cycles 成本不能直接套到即時引擎預算。
