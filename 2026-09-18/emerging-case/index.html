#06 · case-study

PS1 式預渲染背景回到 Unity：用 Blender 高模離線渲染換取遊戲端低成本

《Static Between Stations》把環境與 cutscene 全部在 Blender 預先渲染，再在 Unity 播放背景影片並疊少量前景互動物件；開發者因此能使用高模掃描與 path-traced lighting，而不必把完整場景幾何與貼圖帶進 runtime。

製作案例 ★★★★☆
完整分析

場景流程

案例把 Blender 場景、掃描資產與 path-traced lighting 全部離線算成背景影像／影片，Unity 端只負責播放背景並放置角色與必要前景物件；相機對位與遮擋關係成為主要技術約束，而不是即時場景的 draw call、LOD 與材質成本。

Production 價值

這種做法特別適合固定或受控視角的敘事遊戲：美術可以使用遠超 runtime 預算的掃描、高模與離線光照，並把每個場景的效能風險壓成近似固定的影片播放成本。它也能降低環境最佳化與跨平台材質調校的工作量。

導入限制

代價是相機自由度、動態光照、可破壞物件與角色遮擋都受限，影片解析度與壓縮也會影響記憶體／I/O。導入前應用一個實際鏡頭測 foreground mask、角色深度、鏡頭轉場、影片解碼與不同解析度，確認這種視覺語言真的符合玩法。

#15 · procedural

Blender Geometry Nodes → UE5：把散佈、道路與建築做成可重用程序美術工具

FastTrack 的程序美術課程用 Blender Geometry Nodes 建立垃圾散佈、拖放道路與建築工具，再透過 Altermesh 把參數帶進 Unreal Engine 5；核心不是單一場景，而是把環境規則包成可快速迭代的 artist-facing tool。

程序化 ★★★★☆
完整分析

程序工具流程

課程用 Geometry Nodes 建立 trash scatter、drag-and-drop road 與 building generator，再以 Altermesh 把 Blender 端的程序參數帶到 Unreal Engine。這把『做一個場景』轉成『做一套可重複使用的美術工具』，更接近技術美術的 production 思維。

Production 價值

道路、散佈與建築都屬於高重複、常改版內容，若規則能參數化，美術可直接在場景中快速換尺寸、密度或組合，而不必每次回到手工建模。對小團隊尤其適合把常見環境任務整理成少量可維護 node group。

導入測試

案例使用 Blender 3.5、UE5.2 與 Altermesh，版本已不是最新，正式採用前要驗證 Blender 5.x／UE5.8 的節點相容、資產同步、cook time、collision、LOD／Nanite、material assignment 與多人版本控制，再決定是否依賴 bridge 或改成離線 bake。
