Meshy Auto Split API 現可直接接受已貼圖任務，但分件後仍不保留原貼圖

Meshy 9/16 API 更新讓 Auto Split 可直接接帶貼圖的 input_task_id，不必先重生無貼圖模型；但切割會重建各部件表面，輸出仍是未貼圖、單色部件，整合流程必須把重新貼圖或材質重建列為後續步驟。

AI 3D ★★★★★
完整分析

API 流程變更

Auto Split 現可直接引用已完成且帶貼圖的 Meshy 任務，省掉過去為了分件而再生成一次無貼圖模型的繞路；對批次資產處理與 API 串接來說，輸入步驟更短也更容易保留同一任務身份。

Production 影響

限制仍很明確：分件會切割幾何並重建表面，因此原始 texture 不會被保留，輸出部件只有單色。若目標是遊戲角色、裝備或道具分件，這代表分件之後仍要安排重新貼圖、材質重投射或人工 UV／材質整理。

導入測試

建議用角色與硬表面各一組已貼圖 GLB 測試分件，記錄 seam、部件邊界、法線、UV、材質槽與重新貼圖成本；若拆分只是列印或幾何編輯，流程收益較高，若依賴原 PBR 外觀則要先確認後處理成本是否抵消 API 簡化。
