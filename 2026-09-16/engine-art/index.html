Unity 大量物件渲染實務：Static Batching、VAT 與自訂 Batch Renderer Group 的取捨

Unity 與 Mega Cat Studios 分享 URP/HDRP 大量物件的效能策略，包含靜態批次、Vertex Animation Texture 與為草地建立自訂 Batch Renderer Group。

Unity ★★★★★
完整分析

引擎工作流

案例從 PC／主機與較弱平台的大量物件瓶頸出發，分別討論 static batching、Vertex Animation Texture 與 Batch Renderer Group；其中草地等高數量重複物件可用自訂 BRG 降低 CPU submission 與 draw 管理成本。

製作價值

這類方法不是單純『少 Draw Call』，而是依物件是否靜態、是否需要變形、數量與可見性決定資料如何送進 GPU。對大量植被、群集道具與城市場景，美術資產規格可以因此更早和 renderer 策略綁定，而不是場景完成後才做效能救火。

平台實測

文章是特定專案經驗，URP/HDRP、目標硬體與內容密度都會改變最佳解。導入前應建立相同場景的 Static Batching、GPU Instancing、BRG、VAT A/B 場景，量 CPU Render Thread、GPU、記憶體與剔除成本，並確認 Shader Graph／自訂 Shader 是否維持相同視覺。
