#02 · ai-3d

3AGameFactory × Meshy：AI Agent 把 Image-to-3D／Text-to-3D 接進 Unity、UE5、Blender 與 three.js

北京大學 OpenDCAI 的 3AGameFactory 以 AI coding agent 串接 Meshy 生成角色與道具 GLB，再送進多種引擎與 DCC；重點是可檢查、可重現的資產介面，而非單次生成展示。

AI 3D ★★★★★
完整分析

生成流程

3AGameFactory 把遊戲需求拆成影像、3D、動作、音訊與程式工作，再由 agent 呼叫對應能力；Meshy 在其中負責 image-to-3D / text-to-3D 的角色與關鍵道具，輸出 GLB 後進入 Unity、UE5、Blender 或 three.js 的後續處理與驗證。

製作價值

這個案例把 AI 3D 的評估焦點從『單一模型好不好看』移到座標、尺度、材質、檔案格式與引擎 QA 是否可攜。對自動化遊戲原型尤其有價值，因為生成失敗與資產修復必須變成可追蹤的 pipeline 狀態，而不是人工臨時補救。

導入測試

來源是 Meshy 的供應商案例，不能把『engine-ready』直接視為商用品質保證；團隊應用同一組角色／道具測試 GLB 分件、骨架需求、UV、材質一致性、碰撞與引擎匯入失敗率，並記錄人工修復時間，再判斷 agent pipeline 的真實節省幅度。

#05 · ai-3d

單張人像 Photo-to-3D 實測：Tripo、Meshy、Hunyuan3D 仍難直接保住可用的人臉 likeness

Layer Journey 以同一張人像測試多個 image-to-3D 工具，結果顯示單張照片可快速建立體量，但臉部 likeness 與 production-ready 細節仍需要人工修正。

AI 3D ★★★★☆
完整分析

生成流程

測試用同一張人像照片分別跑 Tripo、Meshy 與 Hunyuan3D，觀察單張 image-to-3D 在頭部比例、五官與整體體量上的結果；這類輸入缺少側面與後腦資訊，因此模型必須自行補全不可見區域。

製作價值

對角色前期 blocking 或快速建立可旋轉參考仍有價值，但若目標是辨識特定人物，單張輸入的 likeness 風險明顯高於一般道具生成。這使多視圖、臉部重建或後續雕刻仍是較可靠的角色 production 路徑。

導入測試

這是單一測試案例而非完整 benchmark，模型版本與設定也會快速改變。建議用正面單圖、正側雙視圖與四視圖三種條件重跑，量測五官偏差、耳朵／後腦補全、拓樸與貼圖返工量，再決定哪一段適合交給 AI。

#07 · ai-2d

Meshy API 9/15 更新：新增 GPT Image 2.5 兩個 tier，並補上 4:3／3:4 圖像比例

Meshy API changelog 在 9/15 新增 gpt-image-2-5-flare / sunburst，Text-to-Image 與 Image-to-Image 同時支援 4:3、3:4；這是 9/14 input_task_id 後的新增 substantive delta。

AI 2D ★★★★☆
完整分析

生成流程

9 月 15 日 changelog 新增 gpt-image-2-5-flare 與 gpt-image-2-5-sunburst 兩個 ai_model 值，並讓 GPT Image 系列在 Text-to-Image / Image-to-Image API 額外接受 4:3 與 3:4，能直接覆蓋更多角色設定稿與直式／橫式概念圖比例。

製作價值

對已用 Meshy API 串概念圖→多視圖→3D 的自動化流程，這次變更主要增加模型選擇與輸出構圖彈性；與 9/14 的 input_task_id 合併使用時，可以降低人工裁切與中間圖片轉接的需求。

導入測試

官方 changelog 沒有提供 GPT Image 2.5 兩個 tier 的品質差異 benchmark；雖列出與 gpt-image-2 相同的 API credit 定價，仍應以同 prompt 測角色一致性、文字遵循、4:3/3:4 構圖與後續 3D 成功率，再決定預設模型。

#12 · ai-3d

KaiNinja：把 TRELLIS.2 類 Native 3D Generator 擴成 Part-Level 輸出，避免先融合再分割

KaiNinja 以 dual-volume representation 解決接觸零件界面無法在單一 O-Voxel 表達的問題，目標是直接生成可分件資產，而非事後 segmentation。

AI 3D ★★★★☆
完整分析

生成流程

研究指出 TRELLIS.2 類 native 3D generator 通常輸出單一融合物件，但編輯、rigging 與 simulation 需要 part-level 資產；KaiNinja 用 dual-volume 表示接觸界面，讓模型在生成階段就能輸出分件，而不依賴後處理 segmentation。

製作價值

如果分件品質能穩定，AI 3D 對遊戲角色與機械道具的價值會從『有一個 mesh』提升到『可個別編輯、材質、骨架與替換的組件』，直接對應目前 image-to-3D 最常見的 production 痛點之一。

導入測試

目前仍是研究成果，不等同於可部署的商用工具；論文摘要與研究頁雖報告 part／whole-object fidelity 改善，仍需檢查程式碼、推理成本、材質邊界與複雜接觸區。建議先以裝甲角色、鞋服與硬表面組件做 part interface 測試。
