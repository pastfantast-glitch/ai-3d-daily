#01 · rendering

《Pokémon LEGENDS Z-A》城市渲染：GPU Instance Culling、三層水面反射與統一 PokéRig

Game Freak 公開密阿雷市的大量實例繪製、階層式 Z 遮蔽、分高度 SSPR、遠距烘焙陰影，以及把人物與寶可夢整合到同一模組化 Rig／Retarget 流程的做法。

渲染 ★★★★★
完整分析

城市渲染流程

團隊把大量重複街燈、長椅與建築附件改以 Instanced Draw 管理，先在 CPU 依群組剔除，再於 GPU 處理大量 instance 並用 indirect draw 決定是否送出；遮蔽資料則以 depth prepass 建立階層式 Z，降低單一大城市中不可見物件的負擔。

美術與 Rig 價值

水面依三個高度群組共用 SSPR，遠距陰影以四方向烘焙到 RGBA 後隨時間混合，讓美術控制與效能預算可以並存；人物與不同骨架寶可夢也透過模組化 PokéRig、重映射與多階段 build 共用資料流，減少大量角色長期維護成本。

導入測試

這些策略依賴場景遮蔽、重複度與目標主機特性。採用前應以代表性城市街區量 CPU/GPU culling、instance group 粒度、深度金字塔成本、不同水位反射記憶體，以及跨二足／四足角色 retarget 後的腳底、重心與極端姿勢品質。

#05 · tools

texLab：UE5 內以明確語意打包 PBR 貼圖，預覽與輸出共用同一執行器

texLab 不依檔名猜 ORM／RMA／ARM，而用 JSON 語意規則、dry-run、輸出 provenance 與 BC7／BC5 round-trip 預覽降低批次 channel packing 的靜默錯誤。

引擎工具 ★★★★★
完整分析

貼圖打包流程

工具以明確 semantic rule 描述來源 map 與 packed layout，避免 ORM、RMA、ARM 或 MSR 僅靠相似檔名猜測；組裝與 repack 共用一套 executor，先 Validate dry-run，再 Execute 寫檔，讓單張預覽、批次執行和最終輸出走相同邏輯。

製作價值

Encoded preview 會顯示 BC7／BC5 壓縮 round-trip 後的結果，輸出同時保存 provenance，因此技術美術可在 UE5 內看見真正交付狀態，而非只看未壓縮暫存影像；對大量材質轉換，這能把 channel 錯位與來源不明從後段 bug 變成前段可檢查狀態。

導入測試

工具目前證據主要來自作者的實際資產開發經驗。採用時應用混合命名、不同解析度、BC5 normal、sRGB／linear、缺少 channel 與網路路徑建立測試組，確認 dry-run、記憶體峰值、Editor responsiveness、覆寫策略與 provenance 在多人專案中都能維持一致。
