《Pokémon LEGENDS Z-A》城市渲染：GPU Instance Culling、三層水面反射與統一 PokéRig

Game Freak 公開密阿雷市的大量實例繪製、階層式 Z 遮蔽、分高度 SSPR、遠距烘焙陰影，以及把人物與寶可夢整合到同一模組化 Rig／Retarget 流程的做法。

渲染 ★★★★★
完整分析

城市渲染流程

團隊把大量重複街燈、長椅與建築附件改以 Instanced Draw 管理，先在 CPU 依群組剔除，再於 GPU 處理大量 instance 並用 indirect draw 決定是否送出；遮蔽資料則以 depth prepass 建立階層式 Z，降低單一大城市中不可見物件的負擔。

美術與 Rig 價值

水面依三個高度群組共用 SSPR，遠距陰影以四方向烘焙到 RGBA 後隨時間混合，讓美術控制與效能預算可以並存；人物與不同骨架寶可夢也透過模組化 PokéRig、重映射與多階段 build 共用資料流，減少大量角色長期維護成本。

導入測試

這些策略依賴場景遮蔽、重複度與目標主機特性。採用前應以代表性城市街區量 CPU/GPU culling、instance group 粒度、深度金字塔成本、不同水位反射記憶體，以及跨二足／四足角色 retarget 後的腳底、重心與極端姿勢品質。

Blender 5.3 原生 Gaussian Splat：PLY／SPZ 匯入、Geometry Nodes 與三種渲染器整合

Blender 5.3 Alpha 將 3DGS 存成 PointCloud 新類型，支援 PLY、SPZ v4、Workbench、EEVEE、Cycles 與程序匯入節點；目前仍無匯出且有色彩與 Transform 限制。

Blender ★★★★★
完整分析

原生資料流程

5.3 把 splat 以 PointCloud 的 3D Gaussian Splats 類型保存，position、scale、quaternion rotation、opacity、base radiance 與 spherical harmonics 都成為明確 attribute；PLY 可自動辨識，SPZ v4 會轉換座標，Geometry Nodes 也新增切換類型與程序匯入節點。

製作價值

Workbench、EEVEE 與 Cycles 共用原生資料結構，掃描或神經重建不必先依賴第三方 add-on 才能進入 Blender 場景；預設 emissive 材質可直接還原外觀，改接 Diffuse BSDF 也能做初步 relighting，讓 3DGS 更容易與傳統場景和節點流程共存。

Alpha 限制與測試

5.3 尚未提供 PLY／SPZ export，效能仍待改善，流程假設 sRGB，低 opacity 搭高 radiance 在 linear pipeline 可能錯誤，Apply Transform 也未正確處理 scale、rotation 與 SH。正式導入前應固定測座標、色彩、SH、變形、記憶體和往返輸出，避免把可顯示誤認為可交付。

Dissectible Anatomy：PBD、SDF 與 Volumetric Splats 做即時切割和撕裂

Purdue 團隊把 cryosection 影像轉為低解析 PBD 粒子與高解析 splat，於 compute shader 更新 SDF，使模型可即時切割、分離與變形，並避免維護網格連接關係。

研究 ★★★★★
完整分析

即時破壞技術

系統以 cryosection 決定 PBD 粒子分布，再建立四倍解析度的 splat；每個 splat 在 runtime 更新到可見表面的 signed distance，切割時以 SDF intersection／subtraction 改變區域，只渲染外殼，省去三角形或四面體被切開後的連接關係重建。

製作潛力

所有粒子、SDF 與 splat 都以可攜式 compute shader 運算，不依賴 CUDA 或特定引擎。除解剖教育外，作者認為中小尺度遊戲破壞、軟體撕裂、怪物肢解與 VFX previs 都有轉用空間，尤其適合視覺可信度高於工程級物理精度的情境。

成熟度與驗證

目前仍是技術示範，教育效果與物理準確度尚未完成實證；平行運算也需在 region、particle 間多次 dispatch 以避免讀寫衝突。導入前應量不同解析度的 VRAM、dispatch 次數、切口細節、碰撞一致性與可控的美術資料格式，再判斷能否轉成遊戲工具。

GPU node 與 legacy CPU 版本分成不同 executable，團隊需確認 graph 相容、顯卡與 driver、30 channel 的下游支援、Smart Material 遷移、GLB 材質及大型 UDIM 專案記憶體，再決定是否替換現有 Substance／Mari 流程。

生成技術

PixGS 不先把 3D 資產壓進 latent space，也不串多個生成階段，而是在每個 diffusion timestep 直接去噪 splat attributes；normal、depth 與高頻結構監督讓外觀與幾何可在 splat 層級同時約束。

製作潛力

若單階段 3DGS 真能維持論文所述品質與約一秒 A100 推論，前期概念資產、novel-view 預覽與大量變體會更快，並減少 cascade 各階段錯誤累積與解碼 artifact。
