# URL intake and persistent editorial queue

The owner can query an article URL from the editorial drawer. Queries compare the published registry, reviewed reserve and pending records. A recommendation only appends URL/source/date metadata to `config/collection-intake.json`, using the current file SHA. It does not fetch a body, approve copy, dispatch Actions or publish. Unknown/unregistered or paused sources must first pass source configuration admission. No new credentials or permissions are required.

The existing Collector is the only consumer. Each normal run selects up to 40 unresolved URLs, oldest attempt first, including recommendations and previous pending records. They are fetched through the existing public-network, topic, twelve-calendar-month, evidence and dedupe gates. Index failure does not prevent a known article URL from being tried. A zero refill budget means zero related article fetches.

`data/ops/collection-monitor.json` retains a URL-only `pending_queue` across successful and failed attempts, including partial source trials. Original run/head/evidence date survive until a fresh evidence packet replaces them. Source bodies remain solely in the original expiring Actions artifact. Old evidence must never be silently rebound to a new run. Actual editorial approval remains a two-pass source review submitted through the existing review PR. A published day does not clear the pending queue or authorize another publication.

An `awaiting-editorial-review` decision is `pending`, not prose rejection. Both session and downstream ledger validators accept only this exact pending reason; it cannot cover canonical publication IDs. The queue is bounded to 1,000 metadata rows, prioritizes unresolved items, and explicitly reports overflow/incomplete coverage. Recommendation storage is capped at 500 URLs and rejects additions when full rather than dropping them.

Source coverage reports configured endpoints, HTTP outcomes, discovered links, article fetches, budget-deferred links and remaining pagination. Last observations persist for sources not scheduled in a later run; dates remain visible. Coverage is bounded configured-index coverage, never a claim of crawling an entire site. The existing Collector's `source_trial` plus `coverage_audit` input checks all active source indexes and at most 40 article bodies after a valid daily DONE. It uses the same concurrency group, emits evidence/monitor metadata only, and cannot create a session or reopen publication. Disabled sources remain visible as disabled, not failures.
